# 從產出物回推前端技術

狀態：2026-10-26使用者選定Vite＋Vue 3＋TypeScript＋Three.js，並說明較熟悉TypeScript。尚未安裝前端套件，版本、現場啟動與存檔方案待確認。3D仍屬選配。

## 使用者提出的產出

1. 各抽選段落輸出CSV，可依用途轉成其他報表格式並上傳Google Drive。
2. 現場有完整流程演出，順序為A棟機車、B棟機車、大腳踏車、小腳踏車，各段獨立保存結果。
3. 每段先展示參與及放棄戶號與數量，再展示可抽車位號碼池與數量，接著演出抽選並展示結果。
4. 最後可選做靜態查詢頁：輸入戶號，查詢停車場車位位置。使用者希望探索Three.js相關函式庫，但此功能優先序最低，不影響主要抽選交付。
5. 傾向離線網頁，具備2D／3D前端呈現能力，不使用常駐VPC。

上述A／B分段為第一輪機車演出順序，不直接套用到AB合併的第二輪機車流程；第二輪演出段落按實際抽選池安排。

## 產出與責任

| 產出 | 建議用途與內容 |
| --- | --- |
| 各段結果CSV | 配位、未配位戶別、剩餘車位，供報表與後續清票 |
| 活動存檔JSON | 年度、輪次、輸入快照、各段狀態、已產生結果與檔案關聯，供恢復及重播 |
| 合併報表 | 所有段落完成後彙總，保留各段原檔 |
| 查詢用結果JSON | 根據最終有效配置產出戶號與車位對應，不直接公開整份活動存檔 |
| 停車場配置資料 | 車位ID、平面位置／座標、區域；後續2D高亮與3D場景共用 |

位置查詢還需要停車場平面圖及車位位置對應，不能只從抽選CSV推得實際位置。查詢頁使用第二輪及繳費清查後確認的有效配置，不能把第一輪已放棄車位仍列為有效。

## 已選方向與實作建議

| 範圍 | 方案 | 理由 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite | 一套畫面組件支援行政流程、投影演出與後續靜態查詢，產出靜態資源 |
| 2D演出 | HTML／CSS／SVG，搭配Vue Transition／TransitionGroup | 名單、數量、號碼池、排序與揭曉易讀，先完成現場操作與錄影 |
| 抽選與清票核心 | 不依賴畫面的TypeScript模組 | 瀏覽器直接運作，核心輸入輸出不綁Vue或3D |
| 狀態 | 明確階段轉移與事件紀錄，以Vue composable管理；跨頁需求明確後再評估Pinia | 抽選段落與動畫進度分開，避免用大量獨立布林值表示互斥狀態 |
| 瀏覽器恢復 | IndexedDB快取＋可攜JSON存檔 | 快速恢復與跨電腦交接分工，瀏覽器快取不當作唯一備份 |
| 檔案保存 | 支援時選本機目錄寫檔，否則檔案下載與確認流程 | 各段保存CSV及JSON，必須處理取消、失敗與重試 |
| 3D選配 | Three.js，先直接整合Vue元件；封裝函式庫另議 | 在Vue畫面中加入可替換3D場景，不讓3D依賴介入抽選規則 |
| Drive | 第一版手動上傳產出 | 維持離線核心，直接API授權及同步之後再評估 |

目前Python第二輪核心可作規則原型與測試參考。正式瀏覽器核心以TypeScript實作，既有Python原型需移植並以相同案例驗證，再決定是否保留Python工具；不為重用原型而強迫現場啟動Python API，也不長期維護兩套正式算法。

## 單段演出與存檔邊界

參與／放棄名單 → 車位池 → 人工確認 → 產生及保存結果 → 動畫揭曉 → 結果總覽／匯出確認 → 下一段。

結果保存與動畫分離：每段只產生一次結果，先可靠保存活動狀態，再按結果播放動畫；動畫中斷可恢復或重播，不再次抽取。尚未保存、保存失敗、已保存待揭曉、已揭曉應可區別；不能按下下載按鈕就宣稱完成落檔。

A棟完成保存後，B棟仍可處於待開始狀態；之後兩類腳踏車各自保存。下一段故障不影響已完成段落。所有段落完成後才彙總整輪結果，亦可重新產生CSV而不重新抽選。

## 離線啟動

使用者已確認以選定年度工作資料夾作為啟動入口，CSV預先放入inputs，按階段確認才讀取並轉成存檔。此需求取代早期逐階段下載作為主要交接操作的提案；直接目錄存取的技術方案仍待實測。詳細規劃見[工作資料夾與存檔](../design/workspace-storage.md)。

離線是網路中斷仍能運作，不等同保證雙擊index.html即可使用所有瀏覽器API。候選方案是預先建置靜態包，現場以本機靜態啟動器開localhost，無需雲端或業務後端。若要求雙擊單檔啟動，需另外驗證打包、模組載入、素材、存檔及瀏覽器權限，不直接假定Vite一般產物可用file://。

字型、音效與動畫素材應隨包提供，執行時不依賴CDN。能否直接寫入指定資料夾取決於瀏覽器支援及使用者授權，需以現場電腦驗證。若下載模式不能滿足存檔確認需求，再評估桌面包裝，不先導入Electron或Tauri。
