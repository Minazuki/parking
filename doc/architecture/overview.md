# 架構方向

狀態：提案，尚未選定框架、部署或 Google API 整合方式。

## 已知條件

每年約執行一次；使用者不希望維護常駐 VPC；已有 Google Drive 帳號，可上傳檔案與下載 Sheets 資料。現場需要錄影與直播展示。

## 優先評估的方案

行政試算表 → 匯出本機檔案 → 抽籤前端匯入 → 現場抽籤與展示 → 本機保存結果與報表 → 上傳 Google Drive 封存。

建議以可離線執行的前端為起點，Drive 先作為資料交換與保存位置。此方案尚未被使用者確認；離線啟動方式、檔案權限、結果持久化與隔年恢復都需實作驗證。

| 選項 | 用途 | 需要處理的問題 |
| --- | --- | --- |
| 本機檔案匯入匯出 | 第一版候選方案 | 行政下載與上傳步驟、版本辨識與遺漏防範 |
| 前端直接讀寫 Sheets / Drive | 後續整合選項 | 授權、帳號交接、網路依賴與存取範圍 |
| 常駐後端 | 目前沒有確定需求 | 年度成本、維運與隔年可恢復性 |

## 設計提案

活動階段、逐步CSV轉換與中斷恢復的規劃，集中於[活動階段與CSV產出](../design/activity-states.md)。目前尚未實作，不能僅以CSV檔名當作活動狀態。

- 不讓直播網路狀態決定核心抽籤是否可用。
- 抽籤結果與動畫分離，支援中斷後恢復及明確標示的重播。
- 封存本輪輸入、結果、報表、必要執行資訊及可重新啟動的程式版本。
- 瀏覽器內部儲存不作為唯一封存來源；仍需外部檔案與備份。
- 正式亂數來源、配位算法、可驗證紀錄與重抽程序待規則討論，現在不指定算法或宣稱公平性已驗證。

## 定案前需驗證

現場電腦與瀏覽器、本機啟動流程、無網路啟動、保存失敗處理、刷新恢復、備份還原與隔年在另一台電腦重新使用。
