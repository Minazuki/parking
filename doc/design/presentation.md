# 前端抽籤演出

目前正式操作流程以[現場模式與獨立清票](live-operation.md)為準：兩次現場各按一次開始，中間清票獨立進行。全站預設黑暗模式。下方逐步投影層保留為管理／校對用途，不作現場必要操作。

狀態：已建立[2D操作工作台](client-workbench.md)、底部進度軸、3D進場與投影演出流程第一版。支援戶別名單、車位池、公開種子、進場及結果五個步驟；音效與進一步揭曉節奏仍待後續調整。

## 使用情境

會議室操作，現場錄影並直播。操作人員按下抽籤按鈕，觀眾需能辨識活動、輪次、參與數量與配位結果。

## 畫面順序

第一輪依序展示A棟機車、B棟機車、大腳踏車及小腳踏車，段落順序圖見下方進度軸規劃。每段各自展示參與及放棄戶號／數量、可抽車位池／數量，各段結果來自已一次性保存的整輪配位，依序演出、展示及輸出報表；不為演出切換重新取seed或提交核心斷點。腳踏車的不參與與機車放棄應使用符合登記欄位的用語。無障礙優先配置及跨棟撥補須在一般抽選名單與車位池中正確反映。

演出、存檔及2D／3D候選技術的分工見[前端技術選型討論](../architecture/frontend-options.md)。以下是每個段落的共用流程。

1. 待機：活動名稱、年度、車位類型與輪次。
2. 名單說明：展示本輪不參加戶別與數量；用語區分不使用與逾期未繳。
3. 數量確認：參與戶數、可抽車位數，以及必要的保留或已配置數量。
4. 播放抽選：整輪已完成一次取seed、計算及保存，依既有結果播放本段戶號與車位演出；取seed操作屬整輪準備。
5. 揭曉：逐戶或整批展示配位，節奏待確認。
6. 結果總覽：展示結果，提供報表與正式結果下載。

## 已確認：整輪drand取值展示

- 按下抽取立即顯示並保存當下本機時間（臺灣時區，含秒），請求quicknet v2 latest，等待時清楚標示取得中。
- 取得後顯示round number、完整64字元hex seed、round預定時間、簽章驗證狀態及固定round查詢網址；文字須能在實況錄影中辨識。
- 同時呈現本機當下時間與round預定時間的實際差值。每輪3秒，正常操作預期約一輪內，不視為延遲保證；超差是否阻擋尚待確認。
- 驗證與存檔成功後才計算及保存正式配位結果，再進入落位演出。失敗顯示原因，不自動換round或改用本機亂數。
- 按鈕時間、請求起迄、round、seed及簽章證據隨完整seed斷點保存；若尚未保存便中斷，重啟回到抽取按鈕，可再取seed。已保存結果的重播讀取原紀錄並標示重播，不請求新seed。詳見[存檔斷點](workspace-storage.md)。

來源與證明的範圍見[Seed與可重現性](randomness.md)，目前驗證工具見[drand v2工具](../tools/drand-seed/tool.md)。

## 行為設計提案

### 底部階段進度軸

操作工作台已實作五個主階段與完成階段回看；投影層另有五個演出步驟與動畫重播，結案顯示仍待後續設計。

- 頁面底部固定一條進度軸，顯示活動目前到哪個階段。
- 主階段與第一輪演出子階段順序見下圖；子階段不代表另外取seed或提交核心斷點。
- 已完成打勾、目前階段高亮、尚未開始灰色、無須抽選標示跳過；不只依顏色辨識。
- 點選已完成階段可查結果或重播，不重新抽選；尚未達條件的階段不能點擊跳過前置作業執行。
- 重新啟動選工作資料夾後，依已保存的活動進度恢復，不依上次畫面位置猜測。
- 活動執行狀態與動畫揭曉進度分開；結果已保存但動畫未完成時，進度軸不能當作尚未抽選。

```mermaid
flowchart LR
    registration["匯入登記"] --> first["第一輪抽選"]
    first --> payment["匯入繳費"]
    payment --> review["清票確認"]
    review --> second["第二輪抽選"]
    second --> closed["結案"]
```

```mermaid
flowchart LR
    a["A棟機車"] --> b["B棟機車"]
    b --> large["大腳踏車"]
    large --> small["小腳踏車"]
```

### 結果與演出

- 結果產生與動畫播放分離；演出途中不重新抽取結果。
- 在揭曉前保存結果；保存位置、成功判定與故障處理尚待設計，不能只靠下載按鈕保證已落檔。
- 重新整理或畫面中斷後能恢復既有結果，重播時清楚標示。
- 正式抽籤執行中防止重複點擊；重新抽籤的權限與程序另議。
- 使用大字、足夠對比與清楚進度；配合實際投影及直播設備試播。
- 演練與正式活動需有清楚標示，演練使用虛構資料。

## 待確認

一次揭曉幾戶、動畫長度與音效、現場操作與投影是否同螢幕、名單是否分頁、公開顯示戶號的格式、報表版型。

## 投影演出第一版

在工作台第一輪或第二輪的車位類型列按「開啟投影演出」。同一Chrome頁面開啟獨立投影層，可切全螢幕，背景工作台暫不可操作。預設沿目前梯次依序展示：

```mermaid
flowchart LR
    households["戶別名單／不參與及無障礙配置"] --> pool["參與數／實際車位／候補池"]
    pool --> seed["取得或回看整輪seed"]
    seed --> arrival["3D進場／物件戶號對話框"]
    arrival --> results["已保存配位／候補／剩餘車位"]
    results --> next["下一梯次／回到工作台"]
```

公開種子步驟尚無整輪結果時，必須明確按下「開始第一輪／第二輪抽選」或沿用已保存種子；呼叫現有工作台命令，不另設抽選API。取值及保存期間停用重複操作與離開按鈕，錯誤留在原步驟供處理。整輪結果保存完成後才允許進入3D；後續梯次回看同一份seed，不重新請求。

進場直接讀目前梯次的保存配位及候補，沿用已確認路線與單一戶號對話框。支援重播、直接落位及手動進入結果；無參與或無項目的池顯示略過原因，不建立3D物件。模型不可用時仍可進入結果總覽。預設不播放音效。

結果後按「下一梯次」切換到下一池，從戶別名單開始；第一輪A棟、B棟、大腳踏車、小腳踏車，第二輪合併機車、大腳踏車、小腳踏車。最後返回工作台；不自動匯入繳費或清票。演出步驟只保留在目前頁面，不寫入0至6斷點，重新開啟可以從頭回看，不表示重新抽選。

`useDrawPresentation.ts`管理步驟與前置條件，`DrawPresentation.vue`整合工作台資料與既有3D播放。Chrome測試覆蓋抽選前名單、車位數、單次抽選、seed展示、重播、下一梯次及空池略過，並確認工作台短高度的seed仍完整顯示。
