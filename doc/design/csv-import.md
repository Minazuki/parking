# 行政CSV匯入契約

狀態：2026-10-26已建立Go讀檔、CSV解析、正規化與API提交，沿用0/與3/的版本1 JSON契約。已唯讀核對現行行政樣板的表頭；未改動遠端試算表。Vue匯入按鈕與完整年度主檔驗證仍待實作。

## 檔案與API

| 操作 | inputs內必要檔案 | API | 前置斷點 | 完成斷點 |
| --- | --- | --- | --- | --- |
| 第一輪登記匯入 | A棟資料.csv、B棟資料.csv、無障礙車位資料.csv | POST /api/v1/csv-imports/registration | 無 | 0/ |
| 第一輪繳費匯入 | 第一輪繳費狀態.csv | POST /api/v1/csv-imports/payments | 2/ | 3/ |

CSV以固定分頁檔名放入年度inputs目錄。Google下載檔名若帶工作簿名稱，操作者須改成表列名稱；不從工作表檔名猜活動年度。API使用空body，不接收上傳內容或任意檔案路徑。啟動、查詢及其他階段不自動讀取CSV。

```mermaid
flowchart LR
    action["明確呼叫匯入API"] --> stage["Service檢查目前斷點"]
    stage --> read["Repository只讀本步inputs"]
    read --> parse["inputcsv解析與正規化"]
    parse --> domain["驗證登記／入帳並準備JSON"]
    domain --> commit["完整提交0/或3/"]
```

登記匯入不讀繳費檔，繳費匯入不重讀A／B及無障礙檔，而是比對0/固定名單。既有標準JSON API仍保留，CSV只是另一個外部轉碼入口。完整提交後不覆寫，重複匯入回409；更正沿用已確認的人工尾端回退流程。

## 格式與共通驗證

- 接受UTF-8（可含BOM）、逗號分隔、LF或CRLF，依標準CSV處理引號及欄內換行。拒絕UTF-16、Big5、NUL及超過1MiB的檔案，不自動猜編碼。
- 第一筆為表頭，必要欄位依下表順序；表頭及欄位值去除外圍空白，括號可全形或半形。
- 不接受改名、重排或未知非空表頭；只允許下列已知的計算區與尾端空欄。未定義欄位若有資料會報錯。
- 全空列略過；缺少戶號卻填了參與／繳費資料屬錯誤，不當作空列。
- 戶號正規化：999-02F、999-02f、999-2皆轉999-2；門牌與樓層為正整數。正規化後不得同表或跨A／B重複。
- 讀取限制於指定年度inputs內的普通檔案，不接受目錄、symlink或路徑跳脫；來源檔保持原狀。

## A棟資料與B棟資料

| 欄 | 表頭 | 接受值 |
| --- | --- | --- |
| A | 戶號 | 正規化為門牌-樓層 |
| B | 機車位 | 放棄／一輪／兩輪，或0／1／2 |
| C | 腳踏車（大） | 不參與／一輪／兩輪，或0／1／2 |
| D | 腳踏車（小） | 同上 |

機車0、1、2分別為放棄、一輪、兩輪；腳踏車0是不參與。空白不套用預設值，也不接受已淘汰的「參與」等模糊值。表格原本已填機車一輪、腳踏車不參與，匯出時保留該選項即可。

可只提供A:D，也可直接匯出整張樣板。現行E欄為空白，F:J為腳踏車名額、已登記、車位數、狀態、處理提醒；此計算區不參與登記解析，只有計算區資料的列不建立戶別。名額依Go名單與固定車位數重新計算，不信任CSV右側快取數字。首輪名單與池由domain準備並排序，不以CSV列順序抽取。

第一輪超額名單不被裁切；池及結果保留所有登記，由已確認算法處理容量與未配位。前端容量警示尚待接入。

## 無障礙車位資料

A:C必要表頭為登記順位、配置車位、戶號。可包含D:E的棟別、撥補B棟車位；這兩欄為外部計算值，Go依A／B名單重算，不作配置依據。

須保留三筆固定資料：順位1配置14、順位2配置2、順位3配置3。無申請者只留空戶號，不刪固定列。列順序可不同，但順位不得重複；有戶號的順位須由1起連續。戶號必須存在於本次A／B名單，且不可重複。

這些檢查確保固定輸入可被程式讀取；資格、取消或超額申請由行政在匯出前處理，系統不提供額外資格核定流程。未配置原位拆分與跨棟撥補依[既有規則](../planning/motorcycle-spaces.md)執行。

## 第一輪繳費狀態

A:E必要表頭為棟別、戶號、機車位已繳費、腳踏車（大）已繳費、腳踏車（小）已繳費。

- 棟別接受A、B、A棟、B棟（英文字母不分大小寫），必須符合0/登記。
- 三個繳費欄接受TRUE／FALSE（不分大小寫）或1／0，轉成JSON true／false；空白或yes等值報錯。
- 必須包含0/的全部戶別，包含放棄／無障礙獲配戶；不可只匯出已繳戶。核取方塊未勾選應匯出FALSE，沒有參與的項目也保留明確FALSE。
- 列順序不限，轉成JSON後依門牌、樓層數字排序；未知、重複或缺少戶號都拒絕提交。
- 3/source保存實際檔名、原始bytes的SHA-256及匯入時UTC時間。BOM、換行等也計入摘要，與轉碼後JSON不同。

繳費匯入只建立3/，不自動清票；清票仍是另一個明確操作建立4/。刪除或修改原CSV不影響已提交3/，也不要求來源檔永遠存在才能恢復。

## 錯誤與留存

CSV值錯誤回400及issues陣列，各項包含fileName、row、column、message；row為原CSV列號，欄內換行按實際行數計算。檔案讀取錯誤使用row 0；CSV為空或表頭錯誤指向row 1。當前實作每次回報第一個錯誤，修正後可再次操作。

錯誤不建立完成斷點；操作失敗與已讀檔名寫入session log。輸入原文及整份戶號名單不寫進log。0/保留正規化登記與配置，不增加來源階段摘要；3/依既有契約保存本次繳費來源資訊。

目前核對的是同次匯入資料的一致性及0/之後的名單覆蓋，不另內建社區完整戶號主檔。若A／B來源本身漏掉住戶，程式無法僅從三份CSV證明完整，正式使用前仍須核對年度名冊。
