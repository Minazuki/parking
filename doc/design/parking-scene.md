# 停車場3D基本場景

狀態：2026-10-26使用者確認B1機車及1F腳踏車模型定案，作為後續展示的配置基準。已使用TresJS／Three.js建立基本場景，支援俯視／斜俯視、旋轉、平移、縮放、定位高亮、分類顯示及無障礙拆分預覽。已支援活動存檔配位的唯讀播放，另保留虛構住戶進場預覽；可整批播放或依目前梯次的戶號查詢。

## MVVM與資料

```mermaid
flowchart LR
    layout["layouts.json<br/>原圖編號與相對位置"] --> model["layout.ts<br/>公尺尺寸與車格生成"]
    model --> vm["useParkingScene<br/>區域、篩選、選取與視角"]
    vm --> view["ParkingView<br/>Vue操作與資訊"]
    view --> scene["TresJS場景<br/>幾何、文字、鏡頭與高亮"]
```

不需要安裝Blender或其他建模軟體：車格與隔間由程式生成，使用Chrome即可查看。將來若加入精細外部模型，可另外匯入glTF／GLB素材。

3D頁面以動態import載入，工作台不會預先載入3D引擎。場景使用正交攝影機及on-demand渲染；文字由本機Canvas字圖集產生，不依賴外部模型或字型下載。

靜態位置及尺寸與抽選結果分開。未來動畫可把Go保存的spaceId對應到模型位置，但場景不請求seed、不執行算法、不改變0至6斷點。虛構預覽不需要Go服務；存檔播放透過本機Go API讀取既有結果。

## 啟動與操作

```sh
npm run dev:client
```

Chrome開啟http://127.0.0.1:5173/?view=parking，或從2D工作台右上方「停車場3D」進入。

- 切換B1機車／1F腳踏車。
- 斜俯視時拖曳旋轉、右鍵平移、滾輪縮放；俯視時拖曳平移。
- 點車格或輸入編號定位，側欄顯示車位、所在排與公尺尺寸。
- 全螢幕只展開模型區，重設恢復整體視角。
- 無障礙拆分開關只改預覽；車位清單可作沒有WebGL時的基本核對入口。

## 住戶物件進場預覽

2026-10-26建立第一版，右側「住戶進場演出」使用999開頭的虛構戶號；不呼叫活動API、不取得seed、不寫入存檔。可整批進場、重播、直接顯示結果、收起物件，以及依戶號只播放該戶記錄。切換區域會停止原動畫。

機車物件在已裁除地板的左上場外集合，沿上方路線進入圓弧與B棟梯廳間的車道口，再循車道主線與車格支線抵達配位；候補留在左上場外。腳踏車從入口外進場，小車位經大27左側的門口進入；候補留在入口外依順位排列。集合區不補回地板，鏡頭在播放時納入場外範圍。

梯廳東側上排與中排（含127）從東側主通道轉入兩排之間的橫向車道，再於目標車格前轉入，避免沿同排車格中心橫切。機車109、108、105、102、99由上方車道接近後轉入；腳踏車北排自門口直接走到目標車位對應的轉彎點，不先前進到共用轉彎點再折返。路線以固定轉折點製作，不在演出時做抽選；位置依路程內插、錯開出發時間，物件到站後車格亮起，並轉成車格方向。播放長度依最後出發物件的路程計算，至少30秒；重播只重設播放時間。使用程式幾何建立小型機車／腳踏車，不下載外部素材；尺寸小於標準車格，避免橫向戶號卡片互相覆蓋。整批播放預設不顯示戶號，點擊物件後頭頂顯示漫畫對話框；同時只開啟一個，另選物件會替換；再點同一物件、空白處或其他場景表面可關閉。對話框不參與點擊命中，點擊可穿透至後方物件。查詢戶號會自動開啟對話框並跟著物件進場，候補仍留在場外。有配位者在移動中只顯示戶號，抵達後才顯示車位編號，側欄選取資訊同步遵循此規則；候補仍顯示候補順位。對話框以細連線連到物件，不使用三角尾巴，以免遮住模型。對話框與文字整體放大為初版的150%；靠近畫面上緣時改在物件下方顯示，避免文字被裁切。對話框使用Three.js Sprite始終朝向鏡頭，依正交攝影機縮放維持可讀的畫面大小；可手動關閉。側欄清單亦可選取物件。動線與視覺節奏可繼續調整。正式存檔已接入；年度綜合戶號查詢、靜態網頁匯出與完整名單的動線校正仍待實作。

邏輯在`models/parking/arrival.ts`，播放與查詢狀態在`viewmodels/useArrivalPreview.ts`，卡片渲染在`scenes/ArrivalCards.vue`。同一配位於整批或單戶查詢時維持相同起點、路線與出發順序。

## 活動存檔結果播放

右側選第一輪或第二輪，再按「讀取活動存檔」。第一輪讀取0與2，第二輪讀取0與6；前後檢查活動ID與進度一致，缺少結果或讀取失敗即停止，不退回示範配位。Go負責驗證存檔，前端映射已保存的配位及候補，不重新抽選、不請求seed，也不寫入任何階段。

播放梯次依第一輪A棟機車、B棟機車、大腳踏車、小腳踏車，第二輪合併機車、大腳踏車、小腳踏車選擇。第一輪另提供已登記的無障礙配位；無障礙拆分依0存檔自動套用，活動模式不能手動切換。略過的池顯示原始reason，無配位／候補的池不能播放。

2D工作台已有結果的車位池提供「播放此梯次3D進場」連結，攜帶輪次與池ID；開啟後只載入資料，不自動播放。查詢範圍限目前輪次及梯次，未混合清票前後結果，尚非最終年度綜合查詢頁。

場外集合位置依名單數量排列於固定範圍；完整名單按出發順序延長播放時間，不以30秒強制截斷。仍需校正大量物件同時進場時的路線與間距。對話框沿用到站後才揭露車位的規則。

`models/parking/saved-arrivals.ts`負責存檔配位映射與車格對應檢查，`viewmodels/useSavedArrivals.ts`負責唯讀載入、輪次及梯次。以虛構活動的真實Go API整合測試確認播放及重載前後0至6的JSON不變，且沒有發送API寫入。

## 全車位路線校對

2026-10-26使用者確認目前進場動畫路線可定案，後續沿用此版路線基準。

「全車位配位測試」以每格一戶998開頭的虛構戶號，覆蓋機車150格、無障礙全拆分153格及腳踏車57格；可用`?view=parking&source=all`直接開啟模式，切換區域後保留全車位測試設定。無須Go或年度存檔，不會發送活動API請求。

提供單一車位重播、1／2／4倍速及播放進度拖曳；拖曳後暫停，方便逐段觀察。單戶或單車位重播直接從該物件的出發時間開始，不需等待前面其他住戶的出發延遲。

`route-audit.ts`檢查路徑線段與其他車格的有向矩形是否相交，排除目的車格。自動測試覆蓋無障礙三處拆分的全部8種組合，以及57個腳踏車位，並放入刻意穿越車格的錯誤路徑驗證檢查器可報錯。畫面顯示穿越其他車格的問題數量。

全格檢查已修正15～20、14及拆分14、2／3、左側島下列、梯廳東側下排（含9）等路線，依各排前方車道進入，不沿其他車格中心橫切。目前驗證的是路徑中心線，尚不包含車身寬度、牆柱欄杆碰撞、車與車避讓；這些仍需實際播放校對。
