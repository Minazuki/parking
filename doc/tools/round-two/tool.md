# 清票與第二輪抽選核心

已實作Python標準函式庫工具[shell入口](../../../tools/round-two.sh)及[Python實作](../../../tools/round-two/py/main.py)，適用機車、大腳踏車、小腳踏車。它是可獨立驗證的核心，不是完整活動狀態機或直播前端，尚未直接串接Google Sheets、CSV或第二輪工作表。

## 目前定位與保留理由

保留為早期清票／第二輪規則原型與回歸測試參考。`prepare`已涵蓋未繳釋出、空位合併及輸入檢查，目前drand／ChaCha20工具僅測試亂數與抽取順序，尚未取代這些功能。

`draw`仍使用SystemRandom，沒有drand證據或seed重現能力，不能當作目前規劃的正式抽選入口。待TS正式核心涵蓋清票、資格輸入、跳過條件及結果約束，並完成測試遷移後，再移除本原型；保留功能並整理為shell入口及`tools/round-two/py/`實作目錄。

## 已確認規則

- 大、小腳踏車均改採兩輪，第二輪不再以第一輪登記超額為前提。此規則取代早期只辦一輪的規劃。
- 第一輪未配位及繳費期限後確認未繳而釋出的車位，按原車種類別進第二輪。
- 第二輪需有該類符合資格且登記兩輪的參與戶；沒有參與戶就跳過該類抽選，保留車位。沒有車位時也跳過，不呼叫亂數。
- 不自行替第一輪登記戶加入第二輪。一般資格、每戶名額、無障礙已配位者及未繳者能否再參加等細則仍需確認。

## 登記選項

機車維持放棄／一輪／兩輪，預設一輪；腳踏車大小改為不參與／一輪／兩輪，預設不參與。三類匯出代碼均為0／1／2。既有腳踏車「參與」轉為「一輪」，不參與保持不變。

樣板及116年度測試表的選單、說明和名額公式已同步更新。名額統計同時計入一輪及兩輪；超額警示仍保留，但不再提示「未超額就不需第二輪」。目前測試表大位35戶、小位13戶都只登記一輪，尚無腳踏車第二輪意願。

## 執行

需要Python 3，無額外套件。範例全部使用虛構戶別，產出寫入被Git忽略的`tmp/`。

```bash
./tools/round-two.sh prepare --input examples/round-two-bicycle.json --output tmp/round-two-prepared.json
./tools/round-two.sh draw --input tmp/round-two-prepared.json --output tmp/round-two-result.json
python3 -m unittest discover -s tests -v
```

工具拒絕覆蓋既有輸出。重跑範例請選新的輸出路徑；正式防止重抽仍須後續活動狀態與封存機制，不能只靠檔案不存在判斷是否已抽。

## 輸入與結果

`prepare`輸入：

- `category`：motorcycle、bicycle_large或bicycle_small，一次一類。
- `review_confirmed`：必須為true，表示操作者已確認期限及入帳清查；工具本身不判定實際截止時刻。
- `participants`：已確認第二輪意願及資格的戶號清單。工具不代替尚未定案的資格核定，不從付款狀態推定資格。
- `allocations`：該類第一輪結果，每筆包含文字household、文字space及明確布林paid。缺漏付款狀態會報錯，不默認未繳。
- `vacant_spaces`：該類第一輪未配位車位。不得與任何已配位車位重疊。

產出保留未繳釋出的原戶號、車位及原因，並合併未配位車位。重複戶號、重複車位、跨類車位、非文字識別及未知類型會報錯。機車一般池的無障礙／拆分相容性需由上游準備階段驗證，本核心不產生機車池。

`draw`讀取準備產出，使用系統亂數打散戶號與車位後一對一配位；記錄完成或跳過狀態、配位、未取得車位者及剩餘車位。結果保存後應直接重播既有結果，不能為演出再次呼叫抽選。
